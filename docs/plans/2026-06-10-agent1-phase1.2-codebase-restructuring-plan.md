# Phase 1.2 — Codebase Restructuring

## Objective
Unify import patterns, enforce barrel exports, resolve path aliases, and eliminate dead code.

## Scope
- `src/store/` — 66 entries, ensure all barrel-exported via `index.ts`
- `src/components/ui/` — 80+ primitives, ensure barrel exports
- `src/engines/` — 129+ lazy-loaded engines via EngineRegistry
- `src/pages/` — 75 entries with lazy routes
- `src/utils/` — formatters, calculations, storage, encryption

## Current State
- Path alias `@/` → `src/` is configured and used
- `EngineRegistry` uses manual switch-case for 39 engines (not auto-discovered)
- `src/store/` likely has missing barrel exports (needs audit)
- No dead-code analysis integrated

## Work Units

| # | Task | Effort | Dependencies |
|---|------|--------|-------------|
| 1 | Audit all directories for barrel export coverage | 1h | None |
| 2 | Add missing `index.ts` files per directory | 2h | #1 |
| 3 | Audit import statements for `@/` alias compliance | 1h | #2 |
| 4 | Run `knip` or `ts-prune` for dead code detection | 1h | #3 |
| 5 | Remove unreferenced exports and files | 2h | #4 |
| 6 | Consider auto-registration for EngineRegistry (file-system scan) | 2h | #1 |

## Acceptance Criteria
- All directories have barrel `index.ts`
- No relative imports like `../../store/` exist (enforce via ESLint `no-restricted-imports`)
- Dead code ratio < 5%
- `EngineRegistry` is auto-discovered or has a registration decorator

## Risk
- Large refactor risk: dead code removal may break functionality not covered by tests
- Mitigation: add test run after each change batch
