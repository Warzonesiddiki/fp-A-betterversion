# Phase 18.3 — Data Encryption Plan

**Agent:** A5 | **Phase:** 18 Security & Access Control | **Subphase:** 3/5
**Created:** 2026-06-10 | **Status:** pending

## Objective

Implement at-rest encryption for persisted data, secure key management, and encrypted storage channels.

## Current State

- masterStorage (`masterStorage.ts`, 6.54 kB) handles persistence
- IndexedDB used for client-side storage
- No encryption layer found for stored data
- Tauri has secure storage available via OS keychain

## Execution Steps

### Step 1: Encryption Strategy

- [ ] Design encryption architecture (Web Crypto API)
- [ ] Choose: per-field vs. whole-database encryption
- [ ] Implement AES-256-GCM for stored data
- [ ] Add data integrity verification (HMAC)

### Step 2: Key Management

- [ ] Implement key derivation (PBKDF2)
- [ ] Derive encryption key from user password/PIN
- [ ] Store salt and IV alongside data
- [ ] Add key rotation mechanism
- [ ] Use Tauri keychain for native key storage

### Step 3: Secure Storage Layer

- [ ] Create encryption wrapper around masterStorage
- [ ] Encrypt before writing to IndexedDB
- [ ] Decrypt on read
- [ ] Add performance benchmark

### Step 4: At-Rest Encryption

- [ ] Encrypt budget data, reports, scenarios
- [ ] Encrypt user settings
- [ ] Encrypt cached API data
- [ ] Leave non-sensitive data (UI prefs) unencrypted

### Step 5: Audit & Testing

- [ ] Verify encrypted blobs are not plaintext
- [ ] Test key rotation flow
- [ ] Test data recovery with known key
- [ ] Test behavior with wrong key

## Success Criteria

- [ ] All financial data stored encrypted
- [ ] Key derived from user password + salt
- [ ] Encryption overhead < 50ms per operation
- [ ] Tauri keychain integration
