# Phase 19.3 — SQLite via Tauri Plan

**Agent:** A5 | **Phase:** 19 Desktop (Tauri) & Native | **Subphase:** 3/5
**Created:** 2026-06-10 | **Status:** pending

## Objective
Evaluate and optimize SQLite access via Tauri SQL plugin vs sql.js, implement migration strategy, and benchmark performance.

## Current State
- `@tauri-apps/plugin-sql` v2.4.0 in dependencies
- `tauri-plugin-sql` with sqlite feature in Cargo.toml
- 2 SQL migrations (initial_schema, cube_schema)
- sql.js v1.14.1 for browser/offline mode
- WASM binary overhead from sql.js

## Execution Steps

- [ ] Benchmark sql.js vs Tauri SQL plugin
- [ ] Test with 10k, 50k, 100k row datasets
- [ ] Measure query time, insert time, memory usage
- [ ] Document results

### Step 2: Migration Strategy

- [ ] Create shared migration runner
- [ ] Add data export/import between modes
- [ ] Handle schema drift detection

- [ ] Add connection pooling

### Step 4: Data Sync Between Modes
