# Phase 12.1 — Plugin Architecture & Registry

**Objective**: Extensible plugin system with sandboxed execution, registry, and lifecycle management.

## Dependencies
- Existing `PluginEngine`
- Existing components: `src/components/plugins/`

## Implementation Tasks

### 1. Plugin Registry (src/plugins/PluginRegistry.ts)
- Plugin manifest format (name, version, hooks, permissions, dependencies)
- Plugin registration/deregistration
- Version conflict detection
- Plugin dependency resolution
- Registry persistence (IndexedDB)

### 2. Plugin Sandbox (src/plugins/PluginSandbox.ts)
- Isolated execution context (iframe-based)
- Timeout enforcement per plugin call
- Memory usage limits
- Allowed API surface definition
- Permission grant UI per plugin

### 3. Plugin Lifecycle Manager
- Install → Enable → Disable → Uninstall
- Plugin update flow (check, download, apply, rollback)
- Activation hooks (onInstall, onEnable, onDisable, onUninstall)
- Health check endpoint per plugin
- Automatic disable on crash/threshold

### 4. Plugin SDK & API
- TypeScript SDK for plugin developers
- Hook registration API (beforeSave, afterCalculate, onRender, onExport)
- Store access API (read-only by default, write with permission)
- UI extension points (menu items, toolbar buttons, custom panels)
- Event subscription API

## Verification
- Plugin installs and activates correctly
- Sandbox prevents global scope access
- Plugin can register hooks and respond to events
- Uninstall cleans up all resources
- Permission denial blocks unsafe operations
