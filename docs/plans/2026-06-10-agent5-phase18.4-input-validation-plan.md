# Phase 18.4 — Input Validation Plan

**Agent:** A5 | **Phase:** 18 Security & Access Control | **Subphase:** 4/5
**Created:** 2026-06-10 | **Status:** pending

## Objective
Audit Zod schema usage, prevent XSS and SQL injection vectors, and add comprehensive input validation.

## Current State
- Zod v4.4.3 in dependencies
- react-hook-form + Zod used in forms
- `zod` listed in form-vendor chunk
- DOMPurify referenced in excel-vendor config
- CSP headers set in Vite dev server

## Execution Steps

### Step 1: Zod Schema Audit
- [ ] Inventory all Zod schemas across the codebase
- [ ] Add schemas for missing forms/API calls
- [ ] Validate financial number inputs (positive, range)
- [ ] Validate date ranges, period formats

### Step 2: XSS Prevention
- [ ] Audit DOMPurify usage in HTML-rendering components
- [ ] Add `dangerouslySetInnerHTML` audit
- [ ] Verify CSP headers are adequate
- [ ] Sanitize user input in cell comments, notes

### Step 3: SQL Injection Prevention
- [ ] Audit sql.js query parameterization
- [ ] Review Tauri SQL plugin parameter binding
- [ ] Audit raw SQL string concatenation
- [ ] Add query builder abstraction

### Step 4: File Upload Validation
- [ ] Validate file types (magic bytes, not extension)
- [ ] Add file size limits
- [ ] Sanitize CSV/XLSX import data
- [ ] Validate imported financial data types

### Step 5: API Input Validation
- [ ] Add Zod schemas for API connectors
- [ ] Validate QuickBooks/Xero API responses
- [ ] Add webhook payload validation

## Success Criteria
- [ ] All user inputs validated via Zod
- [ ] Zero `dangerouslySetInnerHTML` without sanitization
- [ ] All SQL queries parameterized
- [ ] File uploads validated by content type
