> the coverage map the project is executed against: every section has a
> current-state verdict, a disposition and a completion gate. It is owned by
> [`docs/PROJECT_AUDIT_AND_EXECUTION_PLAN.md`](PROJECT_AUDIT_AND_EXECUTION_PLAN.md)
> (Part II); where they disagree, the plan's measured evidence wins and this
> annex is the bug.
>
> **Status vocabulary (evidence, not opinion):**
> `WORKS` proven wired + tested · `PARTIAL` built, gaps named · `UNWIRED`
> code exists, no consumer · `MISSING` no code · `DECIDE` conflicts a standing
> DEC or needs an owner ruling before any build · `EVIDENCE-OWED` a prior
> audit claimed closure; the witness must be re-run in this tree.
>
> **Zero-compromise rule for this annex:** no row may end the project as
> PARTIAL/UNWIRED/MISSING inside the supported scope. Every row terminates as
> (a) WORKS with gate evidence, (b) EXPERIMENTAL — labelled in-product, or
> (c) RETIRED/NOT-SUPPORTED by an owner DEC recorded in
> `docs/discovery/decision-log.md`. Silence is not a disposition.
