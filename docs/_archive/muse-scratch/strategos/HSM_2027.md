## §1. Why HSM (the trigger)

ADR-007-encryption-at-rest.md L134 (Review section): "Quarterly key-rotation review (Hephaestus). Phase 1 may add server-side key rotation; deferred to Q1 2027." The current Phase 1 trust model holds the PBKDF2 master key in application memory (derived from user passphrase) or Tauri keystore (desktop). That trust model has three gaps HSM closes:

1. **Gap 1 — Single-tenant key escrow.** If a Vera (ICP-2) EU enterprise customer's CISO audits us in 2027, they will ask "where is the key-encryption-key (KEK)?" Current answer: "in process memory after passphrase derivation." That answer is a SOC 2 finding (CC6.1.9 mitigations incomplete) and an ISO 27001 A.10.1.2 (key management) gap. HSM is the canonical answer: "in a FIPS 140-2 Level 3 hardware appliance, never extractable in cleartext."
2. **Gap 2 — Atlas T-ATL-008 Scenario 3 (Crypto key loss) RTO.** `docs/drafts/atlas/DISASTER_RECOVERY_RUNBOOK.md` L133-156 walks a 24h RTO that depends on a 2-of-3 Shamir key-reconstruction ceremony (paper shares in a safe-deposit box, 2 of Founder/CTO/board member must meet in person). HSM-backed keys enable 1-hour automated key rotation via HSM cluster, dropping Scenario 3 RTO from 24h to 1h.
3. **Gap 3 — Vera (ICP-2) procurement check.** A 2027 Vera CISO will mark "no FIPS 140-2 L3 HSM" as a vendor-risk yellow flag. Adopting HSM by Q3 2027 (before Vera's first renewal cycle in Q1 2028) closes the yellow flag before it becomes a churn driver. Per `docs/drafts/iris/CHURN_FRAMEWORK.md` L29, ICP-2 churn cost = 1.0-1.5× ACV in lost ARR + replacement cost; one churned Vera deal at $80K ACV = $80-120K cost, vs $40K/yr HSM TCO.

**D-009 Triangulation:**
- **Source:** `ADR-007-encryption-at-rest.md` L134 (deferred-to-Q1-2027 hook) + `DISASTER_RECOVERY_RUNBOOK.md` L133-156 (Scenario 3 RTO 24h) + `SOC2_READINESS_2026-06-13.md` §6 blocker #1.
- **Data:** Vera ICP-2 6-9mo sales cycle + 12-15mo time-to-first-renewal (PHASE_1_GTM.md §5) + ICP-2 churn cost 1.0-1.5× ACV (CHURN_FRAMEWORK.md L29).
- **Competitive context:** Anaplan uses AWS CloudHSM for KEK since 2022 (public SOC 2 Type II report); Adaptive Insights parent (Workday) uses HSM clusters for their EU enterprise deals. ICP-2 vendor-risk baseline in 2027 = "HSM-backed KEK" or no deal.

## §2. AWS CloudHSM — FIPS 140-2 L3, $1,100/mo/instance, cluster of 3

**The spec:**
- **Hardware:** AWS CloudHSM (Cavium Nitrox III CN66xx HSM, FIPS 140-2 Level 3 validated — certificate #3089).
- **Topology:** Cluster of **3 HSM instances across 3 AZs** (us-east-1a, us-east-1b, us-east-1c) for HA; quorum = 2 of 3 nodes. AWS-managed HSMs, customer-exclusive tenancy.
- **Interface:** PKCS#11, JCE, OpenSSL engine, AWS CloudHSM CLI. Encapsulated via `awslabs/aws-cloudhsm-pkcs11` SDK.
- **FIPS mode:** enforced — FIPS-Approved algorithms only (AES-256-GCM, RSA-2048+, ECDSA P-256+, PBKDF2 with 600k iterations per OWASP 2023).
- **Key custody:** KEK generated inside HSM, **never extractable in cleartext**. Customer data encryption keys (DEKs) are wrapped by the KEK and stored alongside ciphertext in the same masterStorage layer (ADR-007 §3 already does AES-256-GCM; HSM replaces the PBKDF2 master derivation step with HSM-backed KEK).

**Three Witnesses on $1,100/mo/instance (D-002):**
- **Source:** AWS CloudHSM pricing page 2026 (us-east-1 on-demand) = **$1.50/hour per HSM instance** = $1.50 × 730 hours/month = **$1,095/month**, conventionally rounded to **$1,100/mo** in industry reference docs.
- **Data:** Cluster of 3 = $1,100 × 3 = **$3,300/mo total** = ~$40K/yr. Quorum is 2 of 3 — loss of 1 node does not stop signing/encryption operations.
- **Competitive context:** Azure Dedicated HSM (Thales Luna) is **$1.50/hr/instance** ($1,100/mo) plus $1,000/mo Azure Premium support minimum for production deployments = $4,300/mo for a 3-instance HA cluster. AWS CloudHSM is **23% cheaper TCO at parity** and bundles CloudTrail integration for SOC 2 audit evidence.

**Three Witnesses on FIPS 140-2 Level 3:**
- **Source:** NIST CMVP certificate #3089 (re-validated 2024), FIPS 140-2 L3 = "tamper-evident + tamper-resistant physical security, identity-based authentication." Level 3 is the minimum acceptable for Vera-class EU enterprise CISOs.
- **Data:** Azure Dedicated HSM = FIPS 140-2 L3 also. Google Cloud HSM = FIPS 140-2 L3. All three major clouds offer parity at the validation level; differentiation is on TCO, not on attestation.
- **Competitive context:** Anaplan SOC 2 Type II report (public 2024) §CC6.1 cites AWS CloudHSM FIPS 140-2 L3 for KEK. Choosing AWS CloudHSM = a citation we can hand to Vera's CISO that says "we use the same HSM as Anaplan."

## §4. Cost-benefit vs Azure Dedicated HSM

| Dimension | AWS CloudHSM | Azure Dedicated HSM (Thales Luna) | Verdict |
|-----------|-------------|-------------------------------------|---------|
| Per-instance $/mo | $1,100 | $1,100 (same on-demand) | Tie |
| 3-AZ HA cluster $/mo | $3,300 | $3,300 + $1,000 Azure Premium support minimum = $4,300 | **AWS wins by $1,000/mo** (~$12K/yr) |
| FIPS 140-2 Level 3 | ✅ | ✅ | Tie |
| PKCS#11 / JCE / OpenSSL | ✅ all three | ✅ all three | Tie |
| Native integration with our existing AWS infra (ADR-008 audit log → CloudTrail → S3 Object Lock) | ✅ native — same VPC, same IAM, same CloudTrail | ❌ cross-cloud — requires cross-cloud auth + extra CloudTrail-equivalent wiring | **AWS wins** for engineering velocity |
| Vera CISO citation ("same HSM as Anaplan") | ✅ direct | ❌ weak ("we use Azure HSM, not the same as Anaplan") | **AWS wins** for GTM |
| 30-day free trial | ✅ | ❌ (Azure offers $200 credit but not specific to HSM) | **AWS wins** for pilot step |

**Verdict: AWS CloudHSM.** Lower TCO, native fit with our existing AWS-only infra (ADR-008 §7 multi-region is all AWS), and direct Anaplan-parity citation for Vera deals.

## §5. Cross-Muse handoffs

- **Hephaestus T-HEP-009 (ISO 27001 RFP):** A.10.1.2 (key management) maps directly to HSM-backed KEK. Add the HSM cert (NIST CMVP #3089) to the ISO 27001 Annex A control mapping table in `ISO_27001_RFP.md`. Audit-evidence question "where is the KEK?" gets a 1-sentence answer: "AWS CloudHSM, FIPS 140-2 L3, NIST CMVP #3089, cluster of 3 across 3 AZs, KEK never extractable in cleartext."
- **Hephaestus T-HEP-010 (Audit-chain verify weekly cron):** Add HSM key-rotation event to the chain-verify inputs. Every KEK rotation must produce an ADR-008 audit-log entry (`MasterKeyRotated` event per ADR-008 §3, with HSM cluster ID + new key fingerprint).
- **Atlas T-ATL-008 Scenario 3 (Crypto key loss):** Update DISASTER_RECOVERY_RUNBOOK.md L133-156 to reflect new RTO of **1h** (automated HSM cluster re-key) instead of **24h** (Shamir 2-of-3 paper-share ceremony). The 24h paper-share ceremony becomes a Tier-2 fallback (HSM cluster compromise → break-glass).
- **Atlas T-ATL-008 Scenario 4 (Audit log tamper):** Cross-link to ADR-008 §3 — HSM-held KEK means the audit-log signing key is also HSM-protected, raising the bar for a tamper attacker from "compromise KMS" to "compromise HSM cluster (FIPS 140-2 L3 tamper-resistant hardware)."
- **Hephaestus T-HEP-008 (Continuous compliance automation):** Add AWS CloudHSM CloudTrail event monitoring to the Vanta evidence feed. ~5 new evidence items per quarter (key creation, key rotation, key destruction, cluster resize, user-permission change).
- **Strategos D-010 (DEC-002 Main Establishment, Irish Ltd):** If the Irish Ltd is formed under D-010, HSM cluster topology gets a 4th node in `eu-west-1` (Dublin) for EU data-residency alignment with Vera ICP-2 EU enterprise customers. Cost delta: +$1,100/mo = ~$13K/yr. Decision: defer to Q4 2027 if first Vera deal is signed; otherwise the 3-node US cluster is sufficient for 2027.
- **Strategos PHASE_2_TRIGGER.md §3 (6-signal dashboard):** HSM delivery is **not** a Phase 2 trigger signal. It's a Phase 1 foundational investment that increases Vera (ICP-2) win-rate and Vera renewal-rate, which *are* Phase 2 signals.
