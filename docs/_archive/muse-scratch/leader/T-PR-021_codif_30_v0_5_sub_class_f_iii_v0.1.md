## §2 Codif 30 v0.5 Cat 4 Sub-Class 1 Sub-Class f.iii — Formal Definition

**Codif 30 v0.5 hierarchy (post-T-MN-021 v0.1 8-cat MECE schema expansion):**

- **sub-class f.iii:** post-SHIP §0a addendum drift (§0a addendum appended post-SHIP, modifying frontmatter embedded values WITHOUT version bump)

**f.iii definition (formal):** A SHIP-COMPLETE spec S has a §0a addendum appended AFTER the SHIP-COMPLETE declaration. **f.iii detection criteria:**

1. The spec has a `§0a` section header (or equivalent frontmatter addendum marker)
2. The `§0a` section was added AFTER the spec was declared SHIP-COMPLETE
3. The `§0a` section modifies frontmatter embedded values (size, lines, SHA256, cite-bundle anchor links)
4. The spec_version is NOT bumped (Codif 22 v0.1 violation — version pinning requires bump on substantive change)

**f.iii severity tiers:**

- **f.iii.1 (single-addendum drift):** 1 §0a addendum appended, 1-2 frontmatter values modified
- **f.iii.2 (double-addendum drift):** 2 §0a addenda appended (§0a + §0b), 3-4 frontmatter values modified
- **f.iii.3 (triple-addendum drift):** 3 §0a addenda appended, 5+ frontmatter values modified (TBD observed)
- **f.iii.4 (cross-spec addendum drift):** §0a addendum references 1+ other specs, modifying their frontmatter state transitively
