## §5 P0 — ADR-010 stale store count (14 vs 24)

**ADR-010:15 says:** "FinPlan Pro persists 14 stores to `masterStorage`"
**ADR-010:264 says:** "A migration that touches a large `dataStore` (10k+ transactions) can take ~1 second on first load"
**ADR-010:320 says:** "All 14 persisted stores — Layer 3 (per-store `version` + `migrate`)"

**Actual (per T-AT-012 v3 audit):** 24 stores with persist (12 in Group A with full triple-middleware + 12 in Group B missing immer).

**Delta:** 10 stores unaccounted for. Likely candidates from Group B (analyticsStore, collaborationStore, dashboardStore, dataStore, driverStore, fxRateStore, notificationStore, scenarioStore, settingsStore, tourStore, uiStore, varianceStore) or new stores added after ADR-010 was drafted.

**Impact:** Layer 3 migration logic under-provisions. If 10 stores are persisted without `version` + `migrate` callback, a breaking change to ANY of those stores will lose user data. This is a **P0 data-loss risk**.

**Fix:** Update ADR-010 to enumerate the 24 persisted stores explicitly, OR add an enforcement rule that the migration runner auto-detects stores at runtime and asserts each has a `version` + `migrate` callback.
