## §2 Sub-Class P — TYPE-INFERENCE-PATH-GAS (NEW)

**Definition:** A 5-ICP SKEPTIC witness cites an engine claim (e.g., "sub-ms lock with SHA-256 chain integrity") without validating the **type-inference path** end-to-end (input → type guard → engine → output → store → render). The witness is technically correct at the engine level but missing the 4-hop inference chain validation.

**Real-world instance (CATCH #221, Apollo TURN 112+ PICK #4 META-WITNESS):**
- Prior witness claimed "PeriodLockEngine.ts:78-80 sub-ms lock (1000 events / 1000 ops = <1ms per op)"
- Type-inference path: `AuditEvent input` → `filter<AuditEvent>({ kind: 'LOCK' })` → `PeriodLockEngine.acquire()` → `LockedPeriod return` → `auditStore.setState({ locked })` → `AuditTrailPage render`
- **Gap:** The witness validated the engine's internal latency but did NOT validate the upstream type guard (`filter<AuditEvent>`) nor the downstream store subscriber (`auditStore.setState`) nor the render path (`AuditTrailPage useAuditStore`).
- **Risk:** If `filter<AuditEvent>` is removed in a refactor, the engine still passes tests but the type inference is broken at runtime.

**Prevention pattern (4-hop inference chain validation):**
```typescript
// Step 1: Document the inference path (1 line per hop)
// event (src/types/AuditEvent.ts:42) → filter (src/engines/AuditLogEngine.ts:128) →
//   engine (src/engines/PeriodLockEngine.ts:78) → store (src/store/auditStore.ts:67) →
//   render (src/pages/AuditTrailPage.tsx:23)

// Step 2: Validate each hop with file:line witness
const inferenceChain = [
  { file: 'src/types/AuditEvent.ts', line: 42, type: 'input' },
  { file: 'src/engines/AuditLogEngine.ts', line: 128, type: 'filter' },
  { file: 'src/engines/PeriodLockEngine.ts', line: 78, type: 'engine' },
  { file: 'src/store/auditStore.ts', line: 67, type: 'store' },
  { file: 'src/pages/AuditTrailPage.tsx', line: 23, type: 'render' }
];

// Step 3: Add to witness §3 (Impl) as required artifact
```

## §3 Sub-Class Q — SPEC-CITATION-D-009-GAS (NEW)

**Definition:** A witness cites a code/line location (per D-009 file:line citation rule) but does NOT cite the **spec** (e.g., `docs/specs/period-lock.md` §SOX-404, Hephaestus `SECURITY.md` §Audit Trail) that defines the requirement being verified. The witness is technically correct at the code level but missing the spec authority chain.

**Real-world instance (CATCH #222, Apollo TURN 112+ PICK #4 META-WITNESS):**
- Prior witness cited `PeriodLockEngine.ts:78-80` for sub-ms lock but did NOT cite `docs/specs/period-lock.md` §SOX-404 (which defines the sub-ms requirement)
- **Gap:** Without spec citation, the witness is "code says X" not "code implements spec Y which requires X"
- **Risk:** If spec is amended (e.g., SOX-404 changes to 5ms threshold), the witness's claim is silently invalidated

**Prevention pattern (spec-authority chain citation):**
```yaml
# Required citation pattern for every 5-ICP SKEPTIC witness
witness_citation_format:
  code_claim: "src/engines/PeriodLockEngine.ts:78-80"
  spec_authority: "docs/specs/period-lock.md#SOX-404"
  spec_quote: "Period lock acquisition MUST complete within 1ms at p99"
  measurement: "1000 events / 1000 ops = 0.7ms p99"
  passes_spec: true
```

**D-007 5-min SLA:** Spec citation lookup is O(1) per claim (1 grep + 1 quote), <2 min total.

## §4 Sub-Class R — CONCURRENT-TEST-MISSING (NEW)

**Definition:** A witness validates a serial code path (e.g., `addEvent(event)` then `getEvents()`) but does NOT validate the **concurrent** code path (e.g., `Promise.all([addEvent(e1), addEvent(e2), ..., addEvent(eN)])` then `getEvents()`). The witness is technically correct in serial but missing concurrent coverage.

**Real-world instance (CATCH #223, Apollo TURN 112+ PICK #4 META-WITNESS + Mnemosyne PICK):**
- Prior witness validated `AuditLogger.addEvent(event)` for single event
- **Gap:** No test for concurrent addEvent (e.g., 1000 events added in parallel)
- **Risk:** SHA-256 chain integrity may be violated under concurrent load if `addEvent` is not atomic

**Prevention pattern (concurrent test addition):**
```typescript
// Required test pattern for every 5-ICP SKEPTIC witness that touches shared state
describe('AuditLogger concurrent addEvent', () => {
  it('preserves SHA-256 chain integrity under 1000 concurrent addEvent calls', async () => {
    const events = Array.from({ length: 1000 }, (_, i) => createEvent(i));
    await Promise.all(events.map(e => AuditLogger.addEvent(e)));
    const chain = await AuditLogger.getChain();
    expect(chain).toHaveLength(1000);
    // Verify each event's prevHash matches the previous event's hash
    for (let i = 1; i < chain.length; i++) {
      expect(chain[i].prevHash).toBe(chain[i-1].hash);
    }
  });
});
```

**D-007 5-min SLA:** Concurrent test addition is O(20) lines per shared-state engine, <5 min total.
