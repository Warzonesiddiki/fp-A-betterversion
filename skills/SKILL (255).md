# Write a PRD

Apply when: planning a new feature, writing requirements, scoping work.

## Structure
1. **Overview** — one paragraph, what and why
2. **User Stories** — As a [role], I want [feature], so that [benefit]
3. **Requirements** — functional + non-functional
4. **Acceptance Criteria** — Given/When/Then format
5. **Out of Scope** — what this feature does NOT include
6. **Success Metrics** — how we measure success
7. **Risks** — what could go wrong

## Rules
- Each requirement is testable
- No implementation details (WHAT not HOW)
- Prioritize: Must have / Should have / Nice to have
- Keep under 2 pages
