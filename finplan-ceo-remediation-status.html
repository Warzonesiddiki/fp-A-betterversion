3. What is still broken

Financial maths accuracy — the most important remaining item

Progress: Currency conversion is now exact. The specific error the auditor found — a conversion returning 0.07700000000000001 instead of 0.077 — is fixed and locked with tests, including one proving 1,000 repeated conversions total exactly, with no drift.

Business risk that remains: Measured precisely, only 2 of 352 financial code modules use our exact-arithmetic component, and 134 places still round using a display function as if it were the truth. Currency is done; budgets, variances, KPIs and report totals are not.

Customer impact: Reports could still be off by small amounts. A CFO who spots a discrepancy will not trust anything else in the product.

Safeguard added: an automatic ratchet now fails the pipeline if anyone adds new imprecise money code, so this cannot get worse while we migrate.

Audit log can be rewritten by an insider

Business risk: The tamper-detection works against accidental or careless changes, but the method is public and unprotected by a secret key. Someone with system access could rewrite history convincingly.

Customer impact: Weakens the evidence customers would rely on in a dispute or a compliance examination.

RESOLVED — Public documentation now matches reality

All six false claims corrected: background processors 7 → 4, calculation engines 202+ → 181, data stores 35 → 38, the coverage claim now states our real 50% threshold, the plugin marketplace is marked NOT SHIPPED, and the false "all tests passing" tick is removed.

Why it stays fixed: a new automated check measures the actual code and fails the release pipeline if any documented number drifts again. Documentation can no longer quietly overstate the product.

Around 20 individual test failures remain

Business risk: Each is an unverified behaviour. So far every one investigated has been either a stale test written before a security feature was added, or a genuine but contained interface bug — none are financial calculation errors.

Customer impact: Low today, but they hide the signal that would reveal a serious regression tomorrow.

Nearly half our advertised features connect to nothing

Business risk: 80 of 188 calculation engines have no route for a user to reach them. They are marketed as product depth.

Customer impact: Customers may buy expecting capability they cannot use.

6. Decisions needed from you

Decision 1 — What to do with 80 unconnected features

Why now: They inflate our public numbers and cannot be honestly marketed.

Option A: Connect them to the interface. Highest cost, largest genuine product.
Option B: Move to an "experimental" area and remove from public claims. Fast and honest.

Recommendation: Option B now, then connect selectively based on customer demand. Reversible: Yes.

Decision 2 — On-device AI feature

Why now: The AI component caused both security vulnerabilities and the broken installation. I made it optional, so the product works without it.

Option A: Leave it optional and off by default. Secure today.
Option B: Rebuild AI on the server where we control the security surface.

Recommendation: Option A now, Option B if AI is a genuine sales driver. Reversible: Yes.

Decision 3 — Correct public documentation now, or after remaining fixes?

Why now: Documentation currently contains claims the audit disproved. Every day it stays is reputational exposure with technical buyers.

Recommendation: Correct immediately. It costs little and removes a credibility risk that no engineering work can offset. Risk if delayed: A prospect or auditor discovers the discrepancy before we correct it.

8. Plain-English glossary

Test suite
An automatic set of checks that runs the software and confirms it behaves correctly.
CI / pipeline
The robot that runs all our checks automatically whenever code changes.
Gate
A rule that blocks a release if a check fails. A gate that does not block is decorative.
Fail closed
When something goes wrong, stop and say so — rather than continuing with possibly wrong data.
Audit trail
The permanent record of who changed which number, when, and what it was before.
Vulnerability (high severity)
A publicly known security weakness that attackers may already know how to exploit.
Regression test
A check written specifically to make sure a bug we fixed never comes back.
Orphan engine
A calculation feature that exists in the code but that no screen or button connects to.
