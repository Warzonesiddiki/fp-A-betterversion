01 · What FinPlan Pro Is

“Eliminate spreadsheets. Replace armies of financial analysts with real-time, accurate, and beautiful financial intelligence.” — project mission statement

FinPlan Pro is an enterprise-grade Financial Planning & Analysis (FP&A) platform. It gives CFO offices, controllers and FP&A teams a single system to budget, forecast, consolidate multi-entity groups, close periods, and produce board-ready reporting — powered by 190 purpose-built financial calculation engines and an embedded AI copilot.

Three ways to run it

  • Native desktop application (Tauri v2 / Rust): a single installer, fully offline and local-first, with data encrypted at rest — for organizations that cannot or will not put financial data in third-party clouds.
  • Responsive web application (React 19 + TypeScript): the same engine library in the browser for teams that prefer SaaS-style access.
  • Server package: multi-user APIs with authentication, role-based authorization and period-close controls (verified by 107 server-side tests).

Who it serves

CFOs, financial controllers, FP&A analysts, auditors and operations finance teams — from single-entity SMEs to multi-entity groups requiring consolidation under US GAAP / IFRS, across 78 pre-configured industry verticals (healthcare, banking, construction, retail, energy, insurance, education, government, manufacturing and more).

03 · How It Works — A Guided Walkthrough

The day-to-day workflow of a finance team on FinPlan Pro, from raw general-ledger data to board-ready insight:

1Connect the ledgerQuickBooks, NetSuite, Xero, Sage, Dynamics connectors or Excel/CSV import.
2Validate & importColumn mapping, blocking validation, duplicate detection — bad money values are rejected loudly, never silently zeroed.
3Plan & modelBudgets, forecasts, driver chains, scenarios, Monte-Carlo; sector templates pre-wired.
4Consolidate & closeMulti-entity consolidation (ASC 810/830), then soft/hard period close with RBAC controls.
5Report & decideTrial balance, P&L/BS/CF, variance analysis, board packs, PDF export; AI copilot answers questions.

The AI Copilot (built-in, every page)

  • Alerts — automatically detects “expenses exceed revenue”, unusually large entries vs. revenue, budgets stuck in review — computed on exact decimal totals.
  • Chat & natural-language queries — “Show me the top 5 variance items this period”, “What's the remaining budget headroom?”
  • Formula & insight suggestions context-aware per page (dashboards, budgets, variance, scenarios).

Reporting & exports

  • Three-statement models (P&L, Balance Sheet, Cash Flow) with balance verification.
  • Budget-vs-actual with variance decomposition and drill-through.
  • Trial balance, journal drill-down, IC reconciliation, board-pack & PDF export paths.
  • Cell-level lineage: every figure traceable back to source entries (audit trail).

Data entry & master data

Real validated forms for debt schedules and leases (blocking validation, exact rate handling e.g. 6.25% → 0.0625), persisted in RBAC-gated stores; GL entries validated before they can ever render as $NaN.

Runs where you need it

Same engine library on native Windows desktop (offline, encrypted local database), in the browser, or against the multi-user server with authorization and period-close enforcement.

Vertical depth as a product strategy

Most FP&A tools are horizontal: the customer rebuilds their industry inside the tool. FinPlan Pro ships 78 sector template systems — dedicated stores, pages and dashboards per industry — so a hospital system, a construction firm and a SaaS company each see their own KPIs on day one. Why “exact numbers” is an industry need, not a detail

Finance software that rounds like a calculator fails audits. During the precision initiative we proved real defects caused by ordinary IEEE-754 float math in working code:

  • An asset revaluation where round(0.075) became 0 — silently wiping accumulated depreciation.
  • Duplicate journal entries that went undetected because 0.19999999999999998 ≠ 0.2.
  • A consolidation reporting a phantom 5.55e-17 imbalance on perfectly offsetting books.
  • A break-even analysis off by 1.6721… vs exact 1.7.
  • An AI alert showing “Net: $-0K” for a real −$500 loss (fixed today).

Every one was caught by our falsification discipline and fixed with regression tests (detail on page 11). This is the difference between a demo product and audit-grade infrastructure — and it is enforced forever by CI.

Honest scope note: decimal exactness today covers all scanned financial paths (97 of 377 modules, 0 raw rounding sites — see page 11). Remaining paths still use standard float arithmetic and are migrated under a tracked backlog. We do not yet claim repo-wide decimal exactness.

AI copilot for alerts, NL queries and insights — but AI never computes money: every figure it surfaces comes from exact engines. “AI-assisted, math-guaranteed” is a defensible position vs. LLM-only rivals.

6 · Modern, fast stack

TypeScript 64.1% · React 19 · Vite · Tailwind 4 · Tauri 2 · 4 web workers keep heavy consolidation/simulation off the UI thread; critical-path bundle compressed <150KB gzip (Brotli).

Positioning summary: versus spreadsheet chaos we offer exactness, audit trails and collaboration; versus legacy EPM suites we offer instant vertical coverage, offline/sovereign deployment and a modern AI-native experience — at a fraction of the implementation burden. 09 · The Precision Initiative — Audit-Grade Money Math (GAP-1)

The single most important quality investment in the product: converting every currency computation from ordinary floating-point arithmetic to a canonical decimal engine — and locking it in with a CI ratchet that can never regress.

25.73%

97 of 377 scanned financial modules on the money primitive · 0 raw toFixed value sites · server 2/23 on decimal.js

How the program works (the ratchet)

  • A CI guard measures decimal adoption across all financial paths (src/engines, store, utils, services, workers, components/ai, and the server package). Adoption can only go up; raw float rounding can only stay at zero.
  • Every migration ships with exact known-answer tests and is falsified: the new tests must FAIL against the old float code before we accept them.
  • Blind spots are treated as process defects: the guard has been extended to workers (session 3), the server (session 4) and the AI copilot layer (today) each time a new surface was found.

17 · How We Build — Evidence-Driven Engineering

For investors performing technical diligence: the process is the asset. The team operates a documented “brutal honesty” protocol that systematically catches false claims — including its own.

1 · Re-run, never trust

Every session re-verifies prior claims with literal command output. Twice this caught “done” items that had never reached main — and completed them for real.

2 · Falsify before you claim

Each migration's new tests must FAIL against the old code (stash test) before being accepted. In PR #29: 63 of 70 new tests failed on old code — proof they test real behavior.

3 · Ratchets, not promises

Quality floors live in CI: money adoption, toFixed count, type-safety, docs-truth. They can tighten, never loosen, without deleting a guard — a visible act in review.

4 · Strict screening

“Not migrated” is a documented decision, not an oversight: every excluded module has a recorded rationale (statistics, percentages, counts, display-only formatting…).

5 · Blind spots are process defects

When raw math was found outside the scan (workers, server, AI components), the response was to widen the guard permanently — three extensions so far.

6 · Everything in writing

GAP_LEDGER.md records per-session evidence, decisions and exclusions; handovers are self-contained documents. Institutional knowledge survives personnel changes.

Due-diligence takeaway: the codebase's quality claims are machine-verifiable on demand. Any figure in this report can be reproduced with a single command (npm run money:adoption, npm run docs:verify, npm test, npx tsc --noEmit) — see Appendix B.
