## 4. In-scope minimum workflow

```text
Sanitized or approved source data
→ controlled import / mapping / validation
→ reconciliation / exception
→ forecast or variance review
→ material decision / assigned action
→ report snapshot / evidence review
```

Anything beyond this flow requires a written change decision. A pilot is not an opportunity to promise all routes, sectors, connectors, or AI capabilities.

## 5. Acceptance criteria

- [ ] Authorized users complete the agreed workflow with no undocumented control workaround.
- [ ] Every pilot report value can drill to permitted source/version/calculation evidence.
- [ ] Data import outcome reconciles to agreed source control totals.
- [ ] Required security/deployment controls are evidenced.
- [ ] User tasks meet agreed completion/confidence targets.
- [ ] Known limitations, support process, rollback, and data exit path are documented.
- [ ] Commercial/next-step decision is recorded.

## 6. Governance

- Weekly sponsor review: blockers, evidence, scope changes, risks.
- Change control: no unapproved scope expansion.
- Data handling: approved/sanitized data only; no credentials in project docs.
- Incident/escalation: named contacts, severity, response expectations.
- Exit: destroy/return data according to agreement; retain only approved anonymized research evidence.
