# Commercial, Implementation & GTM Contract — FinPlan Pro

> **Status:** DRAFT HYPOTHESIS · **Purpose:** Ensure a $500k+ ambition is supported by a repeatable buyer outcome, not feature volume.

## Commercial principle

Price follows provable economic value, risk reduction, implementation scope, support commitment, and deployment responsibility. It cannot be inferred from engine/route counts.

## Required commercial evidence

- ICP and buyer/champion/economic-owner map.
- Quantified current-process cost, close/forecast delay, risk, and tool/consulting spend.
- Competitive alternative and switching trigger.
- Paid pilot or LOI with implementation assumptions.
- Packaging: platform, entities/users/modules, deployment, implementation, support/SLA, data migration, connector scope.
- Procurement/security/legal requirements and expected cycle.

## Implementation method

`Discover → Data/Control Assessment → Foundation → Import/Reconcile → Configure Model/Workflow → Parallel Run → Train → Pilot Close/Forecast → Acceptance → Hypercare`

Every implementation has named customer/FinPlan owners, source-system contract, success measures, migration/rollback plan, data-quality gates, training, support escalation, and acceptance evidence.

## Outcome metrics

Time-to-first reconciled actuals; close duration; forecast cycle duration; manual reconciliation hours; report preparation time; decision/action closure; data-quality exceptions; user task success; customer support burden; renewal/expansion signals.

## Packaging hypothesis

Start with a controlled pilot and implementation statement of work. Treat $500k+ enterprise package as unvalidated until repeatable evidence shows value, security fit, deployment scope, support cost, and buying process. Do not lead with perpetual license claims before commercial validation.
