# Vertical Certification Standard — FinPlan Pro

> **Status:** DRAFT HYPOTHESIS · **Purpose:** Stop shallow sector-page breadth from becoming unsupported market claims.

## Certification rule

A vertical is “supported” only when every item below is evidence-backed. Until then it is configurable, experimental, or unavailable—not certified.

| Certification area | Minimum evidence |
|---|---|
| Market pain / ICP | primary interviews, target workflow, commercial rationale |
| Domain model | metric dictionary, dimensions, accounting/operational assumptions, SME owner |
| Templates | tested plans/forecasts/reports and guided setup |
| Data/integration | source mapping, validation rules, sample sanitized data, connector/import path |
| Controls | policy/close/reporting/compliance requirements scoped and reviewed |
| UX | persona tasks, terminology, workflow, accessibility validation |
| Calculations | golden datasets, precision/reconciliation, edge cases, versioned engine evidence |
| Reporting | certified KPI/report definitions and board/management outputs |
| Documentation/support | user guide, implementation guide, known limits, support runbook |
| Commercial | packaging, implementation estimate, reference/design partner evidence |

## Portfolio policy

Certify no more than five verticals concurrently. Select them by validated pain, sales path, data availability, domain expertise, and implementation repeatability—not existing route count. Every certification expires/reviews annually or when policy/regulation changes.
